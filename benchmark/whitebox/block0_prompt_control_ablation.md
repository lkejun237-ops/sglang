# Block0 独立控制：480 同服务协议对照

H100 Encoder + H200 DiT/Decoder，三个录制 case 各两轮，每轮三次切词。
旧队列和独立控制各 6/6 轮、18/18 次切词通过，全部 lease 已释放。
同 case/轮次/版本逐项核对 seed、cache key 和 L1 hit 一致；48 条首帧/切词缓存回执全部命中。
这是同一服务上的协议消融，不是历史源码重新部署的 baseline，也不是独立离线推理。

旧路径实际切换边界为 51/102/153；独立路径为 17/34/51。旧路径为切词跳过 2,352 个捕获帧，独立路径切词跳过为 0；正常 latest-wins 捕获覆盖仍存在，不能写成“所有捕获帧均保留”。

主要收益来自切词控制不再等旧队列排空：`source_ready` 从秒级降至几十毫秒。
该回执仅代表 Encoder 已交接候选、允许供帧，不等于 DiT 已采用条件或历史 KV 已准备完成。
DiT 首输出计算中位数基本不变（约 1.54 s），Decoder VAE 约 28 ms，不能将 TTFF 改善说成算子加速。
独立路径首个 source 派发至新 RGB 仍有 2.38–7.82 s，其中包含旧工作收尾、输入/输出链路等待和新条件计算；现有记录未完整拆出每一项，差额不臆称纯网络或 Decoder 耗时。

独立路径 Encoder 读取查询结果阶段 22.393–55.786 ms（中位数 39.133）；它不是 Room 查询往返的独立计时。
旧路径这项同口径切词记录缺失，留空，不拿实际缓存读取的 7–8 ms 冒充含排队的查询总延迟。
结合全部 source_ready 在 22.4–57.0 ms 返回、17 帧执行边界，以及阻塞模型队列仍可查询的 CPU 回归，支持当前 SP1 独立查询不受原模型队列串行阻塞。
完整 Room→查询返回的专用跨度仍未单独采集，不能给出虚构的精确查询总耗时。
