## 部署决策矩阵

`E2 + SP2` 表示两张 source Encoder 卡、两张 DiT/Lynn Decoder 卡；
Qwen 是独立进程，可与一张 Encoder 共卡。所有方案都是**单活跃会话**，
不按多用户并发规划 KV 或调度。以下均为 NVIDIA CUDA、完整 50 层 BF16 视频模型；
未经说明，不启用 CPU/layerwise offload、FSDP 或量化。

| 目标硬件 / 实际设备 | 部署选择 | 已有显存观察（每卡） | 验证状态与选择依据 |
| --- | --- | --- | --- |
| H100 目标 / 上海 L20Z，SM90，81,559 MiB（79.65 GiB） | 480 档优先复现 E1 + SP2 低显存组合：remote Qwen、weights-free AdaLN、Lynn、W6/sink3、四步、prompt prefix=5；无 KV pool、无 Graph | DiT driver 采样峰值普通生成 74.52 GiB、一次早期 prompt 切换 74.66 GiB；Qwen/E1 卡约 61 GiB | **历史完整服务组合通过 832×480、720 帧**；完整服务的 736、连续/晚期切换与新 launcher/head 未验证。[证据 A](#证据入口)。另有 PR #356 的 **480/736 Decoder 组件验证通过**，见下节；不能据此增加完整服务输入或缓存容量。 |
| H200 目标 / 上海 L20X，SM90，143,771 MiB（140.40 GiB，driver） | 控制卡数时从 E2 + SP2 开始；先按目标质量固定窗口和步数，再决定是否采用 Graph 实验配方 | 旧 W6 四步 eager：DiT 进程 lifetime peak allocated 最大约 109.56 GiB；最新 W5、先四步后一步 Graph：测速后 DiT 整卡驻留约 120.12 / 120.02 GiB；Encoder+Qwen 63.22 GiB、另一 Encoder 10.49 GiB | 两档 832×480 / 1280×736 都有实测。**最新值是驻留快照，运行峰值未测**；W5/单步改变生成语义，视觉质量未验收。Graph 使用运行时补丁，不能当作主线默认。[证据 B](#证据入口)。另有 PR #356 的 **480/736 Decoder 组件验证通过**，见下节。 |
| 同一 H200 目标 | E2 + SP4 用于比较四步吞吐或分摊 DiT 显存，须使用已冻结的实验补丁 | W6 四步：Graph lifetime peak allocated 最大 74.50 GiB（480）、75.72 GiB（736）；reserved 最大 80.69 / 81.32 GiB | 480 的 Graph 吞吐比同条件 eager 高约 21–23%；736 未见收益。**整段 RGB 不等价、画质未验收**。当前主线 weights-free 仍只准入 SP1/SP2，SP4 属实验方案。[证据 C](#证据入口) |
| B300 目标 / 泰国 L20D，CUDA CC10.3，274,113 MiB（267.69 GiB，CUDA 可见） | 优先用 E1 + SP2、remote Qwen、weights-free AdaLN、Lynn；固定需要的窗口和 prefix 容量，再比较 E2 + SP2 / Graph | 最近固定五 latent 重建验证：W6、四步、832×480/120 帧，source 路径 allocated 峰值 90.940 / 91.016 GiB；普通 block 路径 95.230 GiB/rank | **该版本与对应短请求通过数值及生命周期检查**；source 有真实 Graph replay，普通 block 在 after_step0 下走 eager。不能把此显存数外推到 736 或长流。商业 B300 SKU 身份未独立确认。[证据 D](#证据入口) |

设备容量以进程内查询为准。云配额中的 H100/H200/B300 是测试目标名，保留实际
L20Z/L20X/L20D 标识，不把它们改写成已核验的商业 SKU。CUDA 可见容量与 driver 总量
可能不同，不混作同一读数。单卡余量按角色检查，不能用所有卡总显存判断能否部署。

### Decoder 拆分（实验布局，未合入默认）

把 Lynn source decoder 放到独立 GPU 进程后，DiT 只收共享内存引用，不再解码也不再
持有像素。2026-10-21/22 在泰国 L20D（CC10.3，274,113 MiB）实测，E1 + SP2、
Qwen 仍在 DiT 进程内、resident AdaLN、W6/sink3、queue2、Graph、720 帧技术负载
（120 帧真实 source 重复六次）、客户端整帧 RGB：

| 布局 | 832×480 稳态 / 全程 FPS | 1280×736 稳态 / 全程 FPS | DiT 每 rank allocated |
| --- | --- | --- | --- |
| E1 + SP2（Lynn 在 DiT 卡） | 20.42 / 19.33 | 8.97 / 8.73 | 178.1 / 197.8 GiB |
| E1 + SP2 + D1 | 25.92 / 23.78 | 11.46 / 10.99 | 172.2 / 188.3 GiB |
| E1 + SP2 + D2 | 26.25 / 24.00 | 11.69 / 11.22 | 172.2 / 188.3 GiB |

D2 相对 D1 只有 +1.3% / +2.0%，落在跨运行方差量级内；收益主要来自把 Lynn 移出
DiT 卡（稳态 +28.5% / +30.4%）。TTFF 增加 0.20–0.33 s，来自 decoder 服务握手。
E1 的 Encoder 走 `unvalidated_group_size` 复制回退，不等同于已验证的 E2 分组。
D1 的下一次 latent 传输不等待前一个 decode job，但共享内存 publisher 容量耗尽时仍有背压。
D2 为避免 tile collective 与 bridge transfer 交叠，下一次 append 在接收 latent 前等待
上一 decode job 完成，因此会阻塞 DiT 的同步发送。该 worker 等待受 `--timeout-seconds`
限制（默认 120 秒），不代表端到端延迟上界；尚未采集 D2 的独立背压耗时。
2026-10-22 在 `e1170da2e3` 上做了三布局 × 两档 × 每次 120 帧、每格两次会话的 smoke：
全部完成，SIGTERM 后 decoder 不残留，decoder 进程落在预期卡上（D1 一张、D2 两张）。
同一布局两次会话逐位一致；但三种布局**彼此不是同一画面**，480p 相对本地解码平均绝对差
2.59–2.74/255（PSNR 33.3–33.9 dB，SSIM 0.941–0.945），720p 为 2.00–2.23
（PSNR 34.1–35.3 dB，SSIM 0.962–0.967），无时间偏移、差异随帧序缓慢增长；
D1 与 D2 之间同样是 2.30/255 量级。差异来源尚未定位，不能把该布局当作与本地解码
逐位等价。未验证：L20X/L20Z、组件级 stage timing、差异根因、当前 mainline 上的确认运行。
上海 L20X（140.40 GiB）要套用该布局，需先把 Qwen 移到独立进程并使用 weights-free
AdaLN，否则 DiT 峰值超出单卡容量。证据：`/cpfs/world-model/sglang/decoder-split/20261021-gpu-r6`
、`20261022-gpu-d2-th` 与 `20261022-gpu-smoke-ec4230cc7d`。

角色边界：部署方用 `--zing-dit-gpus` 与 `--zing-decoder-gpus` 显式指定每个角色的物理卡，
两者都是调用方 `CUDA_VISIBLE_DEVICES` 中的**序号**（不是 `nvidia-smi` 编号），例如：

```bash
CUDA_VISIBLE_DEVICES=0,1,2 sglang serve --model-path MODEL_PATH \
  --num-gpus 2 --sp-degree 2 \
  --zing-dit-gpus 0,1 --zing-decoder-gpus 2
```

launcher 只做翻译与校验，不替用户分配：DiT 卡数必须等于 `--num-gpus`，两个角色不得共用同一张卡，
并且 decoder 只能在单节点上使用。Decoder 不配置时保持与 DiT 同卡。编码、解码能力及各自的进程入口彼此独立；
会话协议不假设“一个角色一个进程”。共用 GPU 不等于合并进程，只有显式配置才会合并。
把 Encoder、DiT、Decoder 统一交给 `launch_pool_disagg_server()` 声明与调度是后续 TODO，本版尚未接入。

## H100/H200 Decoder 已验证范围

2026-10-22，[PR #356](https://github.com/seedleap/sglang/pull/356) 的生产源码
`c3cc5714eb25` 已在 H100/H200 目标上通过 **完整 26 层 Lynn Decoder 的 SP2/TP1、
BF16 组件验证**；对照 baseline 为 `f74dde991573`。这是该 PR 的验证证据，
不表示当前 main 已包含该融合实现或通过相同验收。

| 目标 / 实际设备 | 实际尺寸 | baseline → 融合 Decoder RGB FPS | 逐组配对增幅中位数 |
| --- | --- | ---: | ---: |
| H100 / L20Z，CC9.0、132 SM | 832×480 | 114.21 → 161.18 | +40.93% |
| 同上 | 1312×736 | 54.31 → 74.84 | +37.83% |
| H200 / L20X，CC9.0、132 SM | 832×480 | 118.92 → 166.88 | +40.33% |
| 同上 | 1312×736 | 56.81 → 78.60 | +38.35% |

两类设备各通过 20 项 GPU 测试和真实启动预编译的 18 组合；每档各 3 个独立双 rank
进程组、每组 3 轮配对。所有 15 个真实 latent 的输出均 finite、与 baseline 逐位相等；
组件级 EOS、取消、断连、注入 rank0 故障清理及下一 stream 检查通过。
两臂固定同一镜像、`step-00002000.pt` 的 EMA 权重、输入、预热与计时，均为 Decoder
回放；FPS 按 latent5–14 的 34 帧除以逐步较慢 rank wall time 总和计算，先取组内、再取
组间中位数。配对增幅逐组计算，与汇总 FPS 的直接比值可有差异。

**本轮 736 实际为 1312×736，与上方完整服务的 1280×736 分开统计。** 736 的冻结
latent 来自历史 10 层 DiT 诊断，Decoder 本身仍为完整 26 层。上述结果不验收完整
50 层 DiT 的生成准确性、默认 offline-AdaLN、完整服务 Graph 回滚/单活跃会话释放复用，
也不提供 TTFF、E2E、Encoder/DiT 阶段或组件常驻/峰值显存结论；这些仍待补测。
时延分位数、原始记录、精确源码和计时边界见[证据 F](#证据入口)。

同一批冻结 latent 已在 H200 上导出 baseline、融合版和并排视频，每档 51 帧、24 FPS，
不循环补帧；转为 RGB8 和编码 MP4 前的浮点输出逐位相等，最大绝对差和 RMSE 均为 0。
视频用于观察 Decoder 改动的一致性，导出过程不重新运行 DiT，也不计入上表 FPS。
736 诊断输入解码后为噪声，两版一致，仅作数值对照，不作为正常画质样例。
同一 H200 作业另通过 3 项真实 CUDA Graph 组件测试，覆盖 eager/replay 逐位比较、
写区间恢复与历史保持、失败后的调用者 stream 恢复；这些组件检查不扩大为完整服务验收。

## 配置时先检查什么

1. **把 Qwen 移出 DiT rank。** 当前主线仍需显式选择
   `--zing-conditioning-mode remote` 并提供服务 URL、expected profile 和 client config。
   独立 Qwen 与 source Encoder 可共卡，但需要把两进程的整卡占用一起考虑。
   [PR #331](https://github.com/seedleap/sglang/pull/331) 的 remote 默认值修改尚未合入，
   不要因文档里的推荐而省略参数。
2. **准备匹配的离线 AdaLN 表。** 主线 #374 已默认 weights-free，部署前按
   [AdaLN 表契约](/docs/sglang-diffusion/zing/specs/ADALN_TABLE)准备目标设备、权重和完整
   schedule 对应的表，检查零 projection storage、零 miss/fallback。
   SP2 历史四分支模型 ready allocated 从 127.90 降到 95.58 GiB/rank，
   节省约 32.32 GiB；这是加载阶段的对照，不能再次从矩阵峰值里扣除，也不代表所有 checkpoint
   都省同样多。更换硬件、权重或采样计划需重建表；Hopper 的表不能直接复用泰国表。
3. **使用 Lynn，避免加载闲置的原生 Decoder。** 主线 #325 已自动跳过该闲置权重；
   旧 TAEH3 已删除，其历史显存只能作历史证据。参考图 VAE 等剩余模块不会因此自动外迁。
4. **先确定输入与 KV 容量，再开 Graph。** 核对实际宽高、window/sink、prefix 上限及
   pool size=1；prompt 切换按主线固定 5 latent 重建。减少 window 或步数会改变模型行为，
   不能作为等价显存优化。Graph 需要额外 reserved 显存；开启环境变量不等于实际 replay。
   通用 `--enable-cuda-graph` 与 Zing 模型专用 Graph 路径也不能混同。

通用开关见[性能默认配置](https://github.com/seedleap/sglang/blob/main/docs/docs/sglang-diffusion/zing/specs/PERFORMANCE_DEFAULTS.md)，
实时请求与尺寸约束见[实时流式接口](/docs/sglang-diffusion/zing/realtime-streaming)。
主线能力优先于历史文档中的默认值；SP4 表准入、Hopper Graph 补丁等必须随对应版本复现。
[PR #369](https://github.com/seedleap/sglang/pull/369) 提供低显存 launcher，但目前仍为 Draft，
launcher/head 尚无真实 GPU 验收，不能作为已合入的一键部署命令。

旧的通用 joint attention 融合 dispatcher/kernel 已移除；`source_first` /
`cross_chunk` 联合执行保留。fixed KV 路径继续逐分支调用 FA4，本次清理未修改
其 attention、Graph 或 KV 生命周期。旧的 `SGLANG_ZING_JOINT_ATTENTION`
环境变量不再控制执行路径，部署时应移除。此次未重跑 480/736 GPU 性能与显存
对照，表中历史结果保留原源码和配置边界。

2026-10-22 / `45f9fd53ba`：上海 H100（L20Z / SM90），BF16、SP2 local 28 heads、
D128；按正式 ledger 的 832×480 / 1280×736 启动两分支和稳定三分支 shape，
四组 fixed attention 组件对照及 Graph replay 通过，删除前后最大误差为 0。
测试提取原实现的 attention 分支循环并调用真实 FA4，使用随机 QKV；不包含全模型、
SP 通信、RGB 或 E2E 性能验收。[范围与原始结果](https://github.com/seedleap/sglang/pull/389)。

## Qwen 媒体预处理

Qwen 使用按角色归一化后的媒体：reference 图片/视频分别沿用
`reference_image` / `reference_video` 面积预算，source presentation（含连续 source
首帧）按 `source` 面积预算做空间缩放并保留 presentation 帧数和 fps。
Prompt 切换复用已归一化媒体；reference 替换仅处理新 reference，沿用初始请求的有效面积配置。
连续 source 后续 RGB 到 VAE 的路径保持原有行为；本改动不保证任意输入流与 Qwen 首帧的尺寸相同。
连续 source 的公开媒体输入收敛为 `source_stream + references + prompt`：
服务始终从首批接受的 RGB 提取 Qwen source 首帧，不接受独立 video preview 或展示图片。
旧 `user_media` 字段（含 null/空列表）明确拒绝，客户端 `--user-media` 与 ready 中的相关能力声明已删除。
有限输入 `zing_request` 保留；其中未选作 reference、也无法归属 source 的视觉媒体在编码前拒绝，调用者不得伪造内部 `origin`。
此 API 收敛版本的 480/736 端到端性能、效果及 Encoder/DiT/Decoder 显存 A/B 尚未验证；
下述组件结果仍限于原预处理版本，不作为本次 API 改动的完整验收证据。

2026-10-22，基于 `a0abf1c85b` 的预处理改动通过上海单卡 H200（实际 L20X / SM90）
组件验证：原始 source 分别为 832×480、1280×736，各取 17 帧并配六张真实参考图；
显式将 `reference_image` / `source` 面积预算设为 65,536，source 归一为 320×192，
验证初始 Qwen/VAE 输入、连续 source 首帧、prompt 更新及 reference 替换。
8 次真实 Qwen、38 次真实 VAE 编码通过，reference 输入尺寸和像素哈希一致。
CPU 作业 `dlcouce8bl26f472`（826 项及 24 个子用例通过），GPU 作业 `dlc910xzfb0tkvqm`；
回查 `oss://leap-world-shanghai/world-model/sglang/evals/pr507-20261022-r1/`。
这不是 480/736 输出性能或完整 DiT/视频效果验收；远端 RPC 网络与流式 VAE append 未做 GPU 验收。
下列历史性能数据保留原版本边界。

prefix/KV 容量和 Graph/offload/compile；只改变本 PR 要测试的因素。常规测量每 case
1 次完整预热、3 次正式；本页历史 H200 对照使用 2 次预热、3 次正式，复现时沿用该次数。
正式 E2E 关闭阶段采集，组件计时另采；不混合有限输入和 continuous-source 的结果。
若要对照本页 H200 Graph 收益，baseline 明确选证据 C 的同配置 eager；W5 单步方案与
泰国两步方案都不能用它计算改动收益。历史 H200 六图长片也不是当前标准七图长片的结果。

综合测速与诊断入口为 `benchmark/zing_h3_causal/benchmark.py`，见
[benchmark 使用说明](https://github.com/seedleap/sglang/blob/main/benchmark/zing_h3_causal/README.md)。
`request/source/dit` 复用原测量工具；`capture/memory` 显式采集和重放运行时分配，
通过 `report --memory-run` 与已有结果合并查看。采集轮与关闭采集后的正式计时分开。
这次整理未补跑 GPU，也未改变部署配方；历史冻结数据不证明新 worker launcher 已通过 GPU 验收。

## 已有速度观测

这些数字用于选实验起点，不构成跨硬件排名；各组采样、窗口和版本不同。
H200 两组均采用英伦 continuous-source benchmark、真实 source＋六张参考图、
不按实时速度限流，含 5s / 30s-wasteland / 30s-town 三个 case。

## 后续 PR 如何维护

对 Zing H3 性能或显存有影响的 PR，必须在同一 PR 更新本页受影响的决策、数字或验证状态。
范围包括权重常驻、Qwen/Encoder/Decoder 布局、KV、attention、Graph、精度、编译与采样默认值。
即使尚未跑 GPU，也要写明受影响行“当前版本未验证”，保留旧数字对应的版本，不能直接沿用为新结论。

每次更新只需：**日期/短 SHA、实际硬件与尺寸、关键配置差异、主要结果、一个 PR/报告/产物入口**。
优先替换相关行，不逐轮追加日志；完整 benchmark 明细放 PR 或已有报告，不在 recipe 重复存档。
每个影响速度或显存的 PR 均需分别报告 480 与 736、同条件整体 benchmark，以及
Encoder、DiT、Decoder 三部分各自的耗时与常驻/峰值显存、baseline/candidate 变化。
Encoder 分项注明 Qwen、参考图 VAE、source VAE；共享进程/整卡显存不可冒称组件独占，
缺项明确标未测、原因及补测计划。表格口径见
[PR 三部分报告格式](https://github.com/seedleap/sglang/blob/main/benchmark/zing_h3_causal/CLIENT_BENCHMARK.md#pr-三部分报告格式)。
重新部署前验证请求完成、取消/断连/EOS 后资源释放及下一会话可用；通过容量或协议测试
不等于通过视觉质量验收。


## PR #367：SP4 当前 Q/K RoPE 的验证边界

#367 已普通合入 2026-10-22 获取的 main `ca939c4b264c351f00535e0176b8b39e9021abfc`；
运行时基线 `39f066d375e04fd07f7a9bc7c6c94e45529107d4` 与该 main 的运行时、benchmark 和测试内容一致。该实验不依赖 #355 的 Encoder 布局。两侧保持相同主线 Encoder、FA4、checkpoint、七图输入、
window=21、sink=3、after_step0、BF16，以及前三块四步 `[1000,750,500,250]`、
之后两步 `[1000,750]`；目标为完整 50 层、720 帧，分别覆盖 **864×480 与 1312×736**。
这两档使用显式派生 case，保留标准七图长片的原始素材和 prompt。832×480 有限输入会触发
原视频与目标的 2% 长宽比限制，因此本轮 480 档改为 864×480，旧 832×480 结果不作 A/B。
736 档的目标输出是 1312×736，原始 1280×720 source 经官方预处理为 1280×704；输入与输出尺寸分别记录。

当前 main 的 weights-free AdaLN 仅准入 SP1/SP2；该 SP4 实验显式使用 `zing_adaln_mode=resident`，
不通过放宽白名单替代表的兼容性验证。需要 KV pool、单活跃会话和足够预热显存；
按历史约 250 GiB/卡的预热需求选择 CC10.3、CUDA 可见至少 260 GiB/卡的四卡目标，
实际设备与峰值仍以本轮回执为准。历史 R27/R28 的 +1.71%–2.46% 不代表当前 main 的收益。

Lynn 依赖必须匹配原生 Zing 的完整 Diffusers 包：提交
`d5baa4fb548294f47dbca49890abd4b291204c60`（版本标识 `0.40.0.dev0`），其中包含
`diffusers.models.autoencoders.autoencoder_kl_minimax_h3`。本轮固定镜像原带的 0.37 缺少该类，
不能仅凭版本导入成功当作可部署；已用上述完整包严格加载真实训练 checkpoint，双方使用相同依赖。

本轮完整模型 A/B 使用官方 `bench_streaming_source.py` 连续 source 接口。标准有限输入
在 864×480 的实测 prefix 为 25,568 行，超过本配方的 16,384 行池容量；1312×736 另因
归一化后 source 1280×704 与 target 不等，被原有池契约拒绝。这些有限接口配置**未通过**，
不以连续 source 的性能替代其兼容性验收，也不在本 RoPE PR 中扩大池容量或改变媒体语义。

最新 main 的端到端 A/B 与独立阶段诊断正在执行，暂不提供新 FPS 或推荐将该实验配方作为部署默认。
正式轮关闭诊断；Encoder（Qwen/reference/source）、DiT、Lynn Decoder 的 Host/CUDA 区间和
