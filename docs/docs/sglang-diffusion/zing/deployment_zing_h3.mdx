## BF16 SP2 的 NCCL 启动配置（2026-11-05）

独立 Encoder、DiT 和 Decoder 的正式 CLI 在初始化 NCCL 前统一设置
`NCCL_MIN_NCHANNELS=2`，删除进程环境中的 `NCCL_MAX_NCHANNELS`、旧别名
`NCCL_MAX_NRINGS` 以及 `NCCL_MIN_CTAS` / `NCCL_MAX_CTAS` 覆盖。
DiT 每个 rank 都执行相同策略，MAX 不设固定值；网络、网卡等部署配置保持不变。
启动日志记录被覆盖的值。此策略有意覆盖部署环境中的 channel/CTA 设置；
仅适用于这些 Zing 入口，不修改其他模型或 LLM 的 NCCL 配置。
NCCL 配置文件不能另外配置上述上限/CTA 覆盖；本策略不改写配置文件，也不修正已经
初始化的 communicator。已有服务需用新版本重新启动。

此前 MIN/MAX=2 来自测试启动脚本，而非 `2851826d1a` 的 Zing 默认值。
复测不在测试启动脚本中重复设置 NCCL，核对实际启动日志后再与同条件基线比较。
当前候选的 832×480 / 1280×736 GPU 性能及 Encoder、DiT、Decoder 耗时与显存矩阵
尚未完成，不将历史 MIN-only 结果视为当前实现的验收。

## 独立服务启动、流控与收尾（2026-11-05）

本组修复独立 Encoder／DiT／Decoder 的启动和会话收尾，不引入共享静态 KV 容量配置。
DiT 在建立 Gloo／NCCL 之前预留服务端口；HTTP／rendezvous 预绑定失败时，leader 保留异常并继续参与内部组初始化，随后与 store 初始化失败共用广播，在模型加载前通知全部 rank 退出。普通 conditioning 拒绝不隔离 worker，模型／CUDA 同步故障仍隔离；早期 init 被拒绝时清理可幂等执行。两个 CPU/Gloo rank 已通过真实 HTTP／rendezvous 端口占用回归；真实多 GPU／NCCL 的启动故障注入仍未验证。

source 与输出尺寸不同时，Decoder 的 `source.consumed` 按原始输入流宽高计算已归还的
RGB 字节，而非输出画幅。仅断开输出 WS 时，Decoder 丢弃迟到的 RGB／credit 并释放
对应引用，仍接收已发送的 NCCL 载荷，直到输入 owner 有序取消；正常输出取消不标记整组故障。
直连 Decoder 的像素绕过输入 WS，故 Encoder 从首个已校验的正帧数 dispatch 回执启动
既有硬时限；继续输入心跳或不发送 playback ACK 均不延长该期限。

释放配对时，Master 先请求 Encoder `quiesce_group`：停止新输入、串行排空已接收工作，
等待 DiT 取消及 Decoder 退出确认，此时保留全部链路；随后并行拆除三个角色的通信组。
正常清理通过幂等重复 `destroy_group` 等到 `disconnected`，不通过空闲状态查询取得新预留。
初始化在首个异步校验前登记到连接，并与输入排空共用 admission 锁；实际 `link.open` 在模型 owner 队列内
重新检查连接状态。排空等待已受理的初始化完成／被拒绝，再等待取消 ACK；不能在 `quiesced` 后新建 owner。
初始化校验失败时允许没有 ledger；普通排空拒绝不标记模型／通信故障。
这是单活跃会话的正确性保障，不改变模型前向、采样或 KV 容量公式；Master 与三角色须共同升级。

**当前合入 main `01ed0ed97a`（含 #517 容量改动）的生命周期组合未进行新的 GPU 验收，也没有本组的速度／显存收益结论。**
历史合并版本 `9b7084342d` 的 H200 两档会话取消、输出断连硬时限和通信组复用数据保留原 SHA，
不能作为这份单独生命周期组合已实测的证明。CPU 回归及历史私有回执入口见
[PR #584 的修复与 CPU 验证](https://github.com/seedleap/sglang/pull/584)，协议见
[连接管理接口](/docs/sglang-diffusion/zing/specs/WORKER_CONNECTION_API)。

## 共享静态 KV 容量与准入（2026-11-05）

通过 `--mem-fraction-static`／`mem_fraction_static` 指定常驻模型与 KV 的静态预算。
两个启动入口均在模型加载前／后清理空闲缓存并测量实际可用字节，再按实际层数、局部 heads、
head_dim 与 dtype 换算一个共享 slot 的总行数，逐 rank 取最小值；prefix、source、target 共用容量。
保留至少 8 GiB 运行时空间，并分别检查分片联合 forward 与每 rank 完整 7,168 维 prefix 的工作区。
具体公式与输入策略见[容量契约](/docs/sglang-diffusion/zing/specs/PERFORMANCE_DEFAULTS#预分配-kv-池的容量字段)。

初始化、prompt／换图和缓存恢复均先检查编码输入边界，再做精确 packing／峰值准入；
过大更新保留当前会话，初始拒绝清理当前请求并允许原服务下一会话恢复。容量拒绝继续处理在途输入 ACK，并按原有取消路径释放当前请求，保留通信组供下一会话使用。
本容量实现已由 PR #517 合入 main；以下 GPU 证据仅属于该容量版本，不包含本节之外的 #584 生命周期组合。普通条件拒绝及客户端输出断开保留原服务，
迟到 RGB／credit 排空并释放引用；真实模型／CUDA 同步或非法协议故障仍隔离。
本组同时包含 source480／output736 的 source credit 几何与早期 init 幂等清理；
初始化排空、端口失败广播、硬时限与 Master quiesce／销组由 #584 交付，组合验证状态见上节。

### Prompt switch Block0 缓存

2026-10-27，`df0f677e97` + 当前工作区：将初始 Block0 准备缓存扩展为启动与运行时切换共用的 `Block0PreparationCache`，实现以下特性：

### Decoder 拆分（实验布局，未合入默认）

把 Lynn source decoder 放到独立 GPU 进程后，DiT 只收共享内存引用，不再解码也不再
持有像素。2026-10-21/22 在泰国 L20D（CC10.3，274,113 MiB）实测，E1 + SP2、
Qwen 仍在 DiT 进程内、resident AdaLN、W6/sink3、queue2、Graph、720 帧技术负载
（120 帧真实 source 重复六次）、客户端整帧 RGB：

| 布局 | 832×480 稳态 / 全程 FPS | 1280×736 稳态 / 全程 FPS | DiT 每 rank allocated |
| --- | --- | --- | --- |
| E1 + SP2（Lynn 在 DiT 卡） | 20.42 / 19.33 | 8.97 / 8.73 | 178.1 / 197.8 GiB |
| E1 + SP2 + D1 | 25.92 / 23.78 | 11.46 / 10.99 | 172.2 / 188.3 GiB |
| E1 + SP2 + D2 | 26.25 / 24.00 | 11.69 / 11.22 | 172.2 / 188.3 GiB |

D2 相对 D1 只有 +1.3% / +2.0%，落在跨运行方差量级内；收益主要来自把 Lynn 移出
DiT 卡（稳态 +28.5% / +30.4%）。TTFF 增加 0.20–0.33 s，来自 decoder 服务握手。
E1 的 Encoder 走 `unvalidated_group_size` 复制回退，不等同于已验证的 E2 分组。
D1 的下一次 latent 传输不等待前一个 decode job，但共享内存 publisher 容量耗尽时仍有背压。
D2 为避免 tile collective 与 bridge transfer 交叠，下一次 append 在接收 latent 前等待
上一 decode job 完成，因此会阻塞 DiT 的同步发送。该 worker 等待受 `--timeout-seconds`
限制（默认 120 秒），不代表端到端延迟上界；尚未采集 D2 的独立背压耗时。
2026-10-22 在 `e1170da2e3` 上做了三布局 × 两档 × 每次 120 帧、每格两次会话的 smoke：
全部完成，SIGTERM 后 decoder 不残留，decoder 进程落在预期卡上（D1 一张、D2 两张）。
同一布局两次会话逐位一致；但三种布局**彼此不是同一画面**，480p 相对本地解码平均绝对差
2.59–2.74/255（PSNR 33.3–33.9 dB，SSIM 0.941–0.945），720p 为 2.00–2.23
（PSNR 34.1–35.3 dB，SSIM 0.962–0.967），无时间偏移、差异随帧序缓慢增长；
D1 与 D2 之间同样是 2.30/255 量级。差异来源尚未定位，不能把该布局当作与本地解码
逐位等价。未验证：L20X/L20Z、组件级 stage timing、差异根因、当前 mainline 上的确认运行。
上海 L20X（140.40 GiB）要套用该布局，需先把 Qwen 移到独立进程并使用 weights-free
AdaLN，否则 DiT 峰值超出单卡容量。证据：`/cpfs/world-model/sglang/decoder-split/20261021-gpu-r6`
、`20261022-gpu-d2-th` 与 `20261022-gpu-smoke-ec4230cc7d`。

角色边界：部署方用 `--encoder-gpus`、`--denoiser-gpus` 与 `--decoder-gpus` 显式指定每个角色的物理卡，
均为调用方 `CUDA_VISIBLE_DEVICES` 中的**序号**（不是 `nvidia-smi` 编号），例如：

```bash
CUDA_VISIBLE_DEVICES=0,1,2 sglang serve --model-path MODEL_PATH \
  --num-gpus 2 --sp-degree 2 \
  --denoiser-gpus 0,1 --decoder-gpus 2
```

launcher 只做翻译与校验，不替用户分配：Denoiser 卡数必须等于 `--num-gpus`，角色之间不得共用同一张卡，
并且分卡只能在单节点上使用。Role 不配置时保持单角色同卡模式。编码、解码能力及各自的进程入口彼此独立；
会话协议不假设“一个角色一个进程”。共用 GPU 不等于合并进程，只有显式配置才会合并。
现已支持通过 CLI（`--encoder-gpus` / `--denoiser-gpus` / `--decoder-gpus`）或 `launch_pool_disagg_server()` 统一声明与编排各角色卡位。

1. **把 Qwen 移出 DiT rank。** 当前主线仍需显式选择
   `--zing-conditioning-mode remote` 并提供服务 URL、expected profile 和 client config。
   独立 Qwen 与 source Encoder 可共卡，但需要把两进程的整卡占用一起考虑。
   [PR #331](https://github.com/seedleap/sglang/pull/331) 的 remote 默认值修改尚未合入，
   不要因文档里的推荐而省略参数。
2. **准备匹配的离线 AdaLN 表。** 主线 #378 已默认 weights-free，部署前按
   [AdaLN 表契约](/docs/sglang-diffusion/zing/specs/ADALN_TABLE)准备目标设备、权重和完整
   schedule 对应的表，检查零 projection storage、零 miss/fallback。
   SP2 历史四分支模型 ready allocated 从 127.90 降到 95.58 GiB/rank，
   节省约 32.32 GiB；这是加载阶段的对照，不能再次从矩阵峰值里扣除，也不代表所有 checkpoint
   都省同样多。更换硬件、权重或采样计划需重建表；Hopper 的表不能直接复用泰国表。
3. **使用 Lynn，避免加载闲置的原生 Decoder。** 主线 #325 已自动跳过该闲置权重；
   旧 TAEH3 已删除，其历史显存只能作历史证据。参考图 VAE 等剩余模块不会因此自动外迁。
4. **先确定输入与 KV 容量，再开 Graph。** 核对实际宽高、window/sink、prefix 上限及
   pool size=1；prompt 切换按主线固定 5 latent 重建。减少 window 或步数会改变模型行为，
   不能作为等价显存优化。Graph 需要额外 reserved 显存；开启环境变量不等于实际 replay。
   通用 `--enable-cuda-graph` 与 Zing 模型专用 Graph 路径也不能混同。

## Ulysses 与 fixed KV 准备链路

以下开关用于同配置逐项 A/B，每个 SP rank 必须保持一致。它们进入 Graph cache key；
更换设置后使用新的服务进程并完成预热。SP 拷贝消除、history 有效行裁剪与跨 Graph
history 复用默认开启，显式设为 `0` 可关闭对应优化；Norm 融合保持默认关闭。

| 开关 | 默认值 | 行为与适用路径 |
| --- | --- | --- |
| `SGLANG_ZING_FUSED_CURRENT_ROPE_KV` | 沿用原门控 | 已有的 current Q/K RoPE 与 KV 写入融合；固定 KV 路径。显式设为 `0` 可测独立 RoPE 与写入的对照 |
| `SGLANG_ZING_SP_DESTINATION_MAJOR` | `1` | QKV 直接打包为 Ulysses 目标布局，接收结果直接作为 attention 输入；Zing batch-one 的 eager 与 fixed 路径 |
| `SGLANG_ZING_FUSED_QKNORM_ROPE_KV` | `0` | fixed 路径中将 QK Norm 移到 SP 后，与 current RoPE、KV 写入合为一个 kernel；BF16、head=128、rotary=96 |
| `SGLANG_ZING_HISTORY_ROPE_LIVE_ROWS` | `1` | fixed history RoPE 只读写有效历史行，跳过池内空余容量；Graph replay 刷新设备上的有效行数 |
| `SGLANG_ZING_HISTORY_ROPE_CROSS_GRAPH` | `1` | pooled fixed 路径跨 Graph 复用连续稳定的历史前缀（通常为 prefix/sink），仅重算剩余有效行；要求 chunk RoPE reuse 开启 |

Norm 顺序调整用于减少中间访存和 kernel 数量。history kernel 仍按池容量启动 grid，
空余行对应的 block 提前返回。跨 Graph 开关另用有界 grid 处理待重算区间，
区间起止行作为设备 metadata 刷新；raw K、有效坐标或物理映射变化时缩短复用范围。
复用状态在整次执行成功后发布，capture 只额外保护会被后续 forward 覆写的复用行。
生产 `Graph=0` 的通用 eager 路径不经过新增 Norm/KV 和 live-history 融合，需与 fixed
链路的 eager microbenchmark 分别解读。复现命令和组件测量范围见
[SP resident profiling](https://github.com/seedleap/sglang/blob/main/benchmark/zing_h3_causal/SP_RESIDENT_PROFILING.md#attention-preparation-ablation)。

### 当前状态：旧共享 API 多 DiT 入口停用（2026-11-03）

旧的“一个公共 HTTP/WS API 入口自动选择多个 DiT”启动及候选路由代码已注释保留，
不再作为部署入口。旧多组 `launch_pool_disagg_server()` 调用会明确报错；
单组启动、其他模型的通用 launcher，以及 Encoder／Decoder 共模型多 service 不属于本次停用范围。
新部署使用独立 worker service，由 Master 通过 HTTP 显式建立 Encoder → DiT → Decoder 通信组；
操作入口见 [Worker group 测试 Master](https://github.com/seedleap/sglang/blob/main/benchmark/zing_h3_causal/WORKER_GROUP_MASTER.md)。

停用前检查发现旧候选路由存在以下故障处理问题：

- **会话释放失败后，重试可能找错 DiT。** 公共 API 在发出释放请求前，就删除了“该会话属于哪个 DiT”的记录。
  例如会话实际运行在第二个 DiT，释放请求超时后，重试可能被路由到第一个 DiT。
  第一个 DiT 返回“没有释放会话”时，上层仍可能将此次 RPC 成功视为清理完成，导致原会话资源没有确认释放。
- **回包超时后，重试可能重复执行。** 请求已发送给第一个 DiT 后，即使只是响应超时，旧逻辑也可能把同一请求再发给第二个 DiT。
  第一个 DiT 可能已经开始处理，因此两个 DiT 都可能执行该请求，而会话归属只记录一个，后续清理也可能遗漏另一个。

上述问题位于旧公共 API 的候选调度与会话释放路径，不是新 worker `destroy_group` 的语义。
目前采取停用旧入口，而非声称已修复其重试算法；重新启用前，必须保证释放确认前保留会话归属、
禁止未经确认的跨 DiT 状态请求重放，并补充释放超时和发送后回包超时的故障回归。
